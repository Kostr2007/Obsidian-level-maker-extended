# Игровые примеры параметров Studio

Шесть PNG сняты **в UZDoom 5.0.3** с ресурсами **Freedoom Phase 2 0.13.0**.
Это подготовленные вручную тестовые сцены, а не результаты запуска генератора
Obsidian с разными seed. В каждой паре меняется один фактор.

| Пример | Меньшее значение | Большее значение | Остальные условия |
| --- | --- | --- | --- |
| Освещение | [144](lighting-low.png) | [208](lighting-high.png) | Одинаковая геометрия и три противника |
| Перепады высоты | [Ступень 8 ед.](steepness-low.png) | [Ступень 24 ед.](steepness-high.png) | Один маршрут, потолок и освещение 192; без противников |
| Количество монстров | [3 противника](monsters-low.png) | [9 противников](monsters-high.png) | Та же комната, освещение 192, один тип противников |

Номера относятся к тестовым сценам. Они не являются готовыми пресетами или
точными соответствиями пунктам Obsidian. В частности, множитель освещения
Obsidian действует на таблицы яркости, а здесь показан принцип изменения света.
Перепады высоты иллюстрируют лестницы, а не настройку высоты потолков.

## Что проверено визуально

Каждый финальный кадр открыт и просмотрен. Проверены отсутствие HUD, оружия,
меню, консоли, чёрных полей, ошибок текстур и случайного изменения камеры.
Первый захват забракован: внутренний viewport занимал часть PNG; вместо обрезки
исправлены параметры окна до инициализации UZDoom и выполнена повторная съёмка.
Тёмный вариант 96 забракован как нечитаемый и переснят при 144. Сцена с девятью
противниками переснята с новой расстановкой, чтобы фигуры не перекрывались.

Все финальные PNG — 1280×720, без ретуши, изменения гаммы и обрезки. Кадр
`monsters-high` независимо переснят повторно: декодированные RGB-пиксели совпали
полностью. Передача изображения в Qt сохраняет пропорции и разрешает увеличение.
Проверка проходимости и баланса по этим иллюстрациям не проводится.

## Воспроизведение

Нужны UZDoom, Freedoom2, Python 3, Xvfb и xdotool. На Linux без физического
дисплея применяется Xvfb. Используются программный paletted renderer, seed 12345,
фиксированная камера `(0, -192)`, угол 90°, скрытый HUD/оружие и `freeze`.
Конфигурация каждого запуска отдельная, пользовательские настройки не меняются.

```sh
# Пересобрать шесть UDMF/WAD и проверить изменение одного фактора в каждой паре:
python3 scripts/dev/capture-gameplay.py --build-only

# Проверить существующие PNG, CRC, разрешение, SHA-256 и контрольные сцены:
python3 scripts/dev/capture-gameplay.py --verify-assets

# Повторить полную съёмку (путь к IWAD нужно указать свой):
python3 scripts/dev/capture-gameplay.py --uzdoom /path/to/uzdoom \
  --iwad /path/to/freedoom2.wad

# Переснять только один кадр:
python3 scripts/dev/capture-gameplay.py --uzdoom /path/to/uzdoom \
  --iwad /path/to/freedoom2.wad --only monsters-high
```

Локальные инструменты текущей облачной среды:

```sh
source /workspace/.obsidian-env/activate.sh
python3 scripts/dev/capture-gameplay.py \
  --uzdoom /workspace/.obsidian-art-tools/bin/uzdoom \
  --iwad /workspace/.obsidian-art-tools/freedoom/usr/share/games/doom/freedoom2.wad
```

Исходные текстовые карты и WAD лежат в `scenes/`. Сценарий генерирует их заново
и проверяет тождество исходников после исключения единственного меняющегося
поля; для количества проверяется добавление только шести вещей. Временные INI,
журналы UZDoom, захваты и отчёт находятся в `build/gameplay-capture/`.
`manifest.json` хранит контрольные суммы окончательно проверенного набора и IWAD.
После пересъёмки нужно снова просмотреть кадры и обновить manifest из отчёта;
проверка автоматически обнаруживает устаревшие суммы.

## Использование в приложении

Studio показывает пару PNG для `ui_arch/float_overall_lighting_mult`,
`ui_arch/steepness` и `ui_mons/float_mons`. Подписи — текст Qt, в картинках
нет надписей. Миниатюра или кнопка «Сравнить крупнее» открывает увеличенный вид.
На небольшом экране изображения располагаются вертикально с прокруткой.
Другие параметры сохраняют текстовую справку; условные Canvas-схемы удалены.
UZDoom и Freedoom не нужны на компьютере пользователя для просмотра примеров:
готовые PNG встроены в ресурсы Qt.

## Проверка интеграции в Studio

Проверены реальные окна Xvfb в обеих темах, поиск с клавиатуры, увеличение
нажатием на миниатюру, открытие Ctrl+I на окне 1050×600, Escape и генерация WAD.
Последние dark/light launch.log пусты. QtTest: 12 passed, 0 failed, 0 skipped;
настоящие изображения загружаются из ресурсов Qt с размером 1280×720, все три
окна сравнения открываются и закрываются. При изменении ширины проверка ждёт
завершения асинхронной компоновки.

После визуального просмотра пересняты и кадры самого Studio: первый поиск
создаёт много делегатов, поэтому слишком ранний захват показывал лишь первую
букву запроса. Ожидание окончательного кадра увеличено; курсор убран с картинок,
чтобы подсказки не закрывали содержимое.

- Инспектор: [тёмная тема](studio-dark.png) / [светлая тема](studio-light.png).
- Увеличенное сравнение: [тёмная тема](studio-comparison-dark.png) /
  [светлая тема](studio-comparison-light.png).
- Окно 1050×600: [тёмная тема](studio-small-dark.png) /
  [светлая тема](studio-small-light.png).

В инспекторе и маленьком окне содержимое прокручивается; увеличенное сравнение
при достаточной ширине показывает пару рядом. PNG сохраняют пропорции.
