# Проверка профилей и уровней усилий

## Обновление политики, 2026-11-07

Уровни усилий не являются названиями моделей. В корневой `.codex/config.toml`
запрашивается `model_reasoning_effort = "ultra"`, в профилях специалистов —
назначенные medium/high; при запуске им явно передаётся `reasoning_effort`.
Профиль `art_director` запрашивает high. Корневая настройка не меняет
существующую сессию автоматически и не должна подменять уровни специалистов.
Описанное ниже ограничение наблюдения остаётся единым примечанием;
повторять его в каждом новом отчёте не требуется. Успешное принятие параметра
запуска не объявляется подтверждением фактического уровня исполнения.

## Историческая проверка исходной конфигурации

Дата задачи: `2026-11-06`. Исходная конфигурация — `81cbc4f`,
`.codex/config.toml` и `.codex/agents/*.toml`.

Профили прочитаны; каждому агенту передано требование прочитать собственный
профиль и рабочий процесс. При запуске через `collaboration.spawn_agent`
координатор явно передаёт `reasoning_effort` и `fork_turns="none"`. Модель
не переопределяется. Инструмент принимает указанные значения; это подтверждает
запрошенную конфигурацию, но не раскрывает фактическую конфигурацию исполнения.

| Роль | Профиль | Явный параметр запуска | Фактический уровень runtime |
| --- | --- | --- | --- |
| `apple_researcher` | high | high, принят инструментом | UNVERIFIED |
| `visual_critic` | high | high, принят инструментом | UNVERIFIED |
| `functional_tester` | medium | medium, принят инструментом | UNVERIFIED |
| `accessibility_critic` | medium | medium, принят инструментом | UNVERIFIED |
| `ui_builder` | medium | medium, принят инструментом | UNVERIFIED |
| Координатор | high по WORKFLOW | Текущий уровень собственной сессии не меняется этим API | UNVERIFIED |

Проверены доступные средства наблюдения:

- `collaboration.list_agents` показывает имя и состояние, без model/reasoning.
- В доступном `CODEX_HOME` отсутствуют локальные rollout/session records и
  SQLite state stores, по которым можно было бы подтвердить настройки дочерних
  сессий. Секретные файлы и значения учётных данных не читались.
- CLI справка `codex agents`, `codex debug` и `codex app-server` не дала
  доступного read-only запроса фактических настроек этих удалённых дочерних
  сессий. Отдельная локальная CLI-сессия не считалась бы доказательством
  конфигурации уже запущенного агента.
- Каждый агент подтвердил отсутствие такого introspection в своём отчёте.

Поэтому утверждение «уровни фактически применились» не делается. Значения
из TOML и принятые параметры запуска не подменяют runtime evidence.
Наблюдаемый максимум одновременных потоков ограничен четырьмя, включая
координатора, как требует конфигурация проекта. Зависшую инициализацию
исследователя возобновили в том же задании; исследование выполнено и отчёт
собран до назначения исправления.

`scripts/dev/check-design-agent-setup.py` проверяет структуру профилей и
каталога; его PASS не подтверждает ни reasoning runtime, ни визуальную
приёмку. Приложение и исправления принимаются отдельно по настоящим логам,
assertions и изображениям.
