# ART-04: контракт экспериментального прототипа

Дата: 2026-11-07. Пользователь разрешил реализацию ART-04 и запросил сравнение
в обеих темах, независимые Visual Critic / Art Director и Functional Tester.

## Один ограниченный шаг

Только шесть значков категорий в боковой панели `--design-preview`.
Существующие глифы — собственный `PreviewIcon.qml`. A воспроизводит исходное
оформление, B добавляет компактную цветную скруглённую подложку и светлый глиф.
Размеры и расположение строк, текста, выбранного фона и focus outline одинаковы.
Увеличение рисунка внутри существующего icon-slot допустимо только без перекрытия
текста, фокуса или края панели. Цвета B могут быть уточнены для контраста;
сохранить смысл существующих цветов, силуэты и всю палитру A.

Решения classic / zebra / original фиксированы. ART-05/06, ползунки, новые
иерархии, размеры панелей, генератор и CONFIG не входят в этот шаг. B остаётся
переключаемым экспериментом. Не вводить постоянный пользовательский параметр.

## Доказательства и критерии

- Реальные текущие PNG A/B: Geometry и Resources, light/dark, 1440×900;
  900×540; текст125%; DPR1.5. Отдельное состояние клавиатурного фокуса.
  Все шесть значков должны быть доступны визуальной оценке хотя бы в одной
  обычной паре; включить выбранные/невыбранные строки и длинную подпись.
- В паре совпадают значения, выбранный раздел/ресурс, inspector, viewport/DPR,
  текстовый масштаб, scroll и focus; sidebar/text/editor geometry сохраняется.
- Не допускать обрезки, перекрытия, конкуренции значков с основным содержимым.
  Сохранить распознаваемые формы и выбранную строку без опоры только на цвет.
- Измерить контраст значимых глифов B с подложками: проектный ориентир >=3:1.
  Не объявлять это измерением всей WCAG-совместимости или правилом Apple о цветах.
- Проверить реальные клики всех категорий, Tab/стрелки/Return/Escape где
  поддерживаются, focus outline и resource grid/list navigation, переключение
  A/B и возврат A после перезапуска. Проверить отсутствие записи стиля в CONFIG.
- Functional Tester: setup validator, build, Qt core, Studio smoke, Preview smoke;
  отдельная актуальная съёмка после commit. Дополнительные проверки — по риску.
- Visual Critic и Art Director независимо читают current-commit PNG + официальные
  Settings изображения MAC-22/23; каждый вправе предпочесть A или B. Для
  интерактивного изменения — bounded accessibility review после основных gates.

## Этапы и владельцы

1. Coordinator сохраняет предыдущее исследование и этот контракт в отдельной ветке.
2. UI Builder (medium) реализует один шаг, запускает необходимые проверки и
   снимает предварительные кадры. Только UI Builder редактирует production QML.
3. Coordinator фиксирует код; Functional Tester (medium) получает чистый commit,
   снимает финальные пары, проверяет поведение и даёт сигнал готовности.
4. Visual Critic (high) и Art Director (high) рассматривают те же пары независимо.
   Accessibility Critic (medium) проверяет фокус/масштаб/контраст в пределах шага.
5. При подтверждённой проблеме — возврат builder, максимум3 итерации; после
   нового изменения повторить затронутые функциональные и визуальные gates.
6. Представить A/B и отчёты пользователю. Принятие B не входит в этот прототип.

Профильные reasoning уровни передаются явно; общее ограничение наблюдения
runtime уже описано в `2026-11-06-agent-runtime.md`.
