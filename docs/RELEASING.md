# Выпуск Obsidian Extended

Релизы выпускает workflow **Qt 6** после успешной сборки и проверок.
Секреты вручную добавлять не нужно: публикация использует встроенный
`GITHUB_TOKEN` с правом `contents: write` только в задании публикации.

## Обычный выпуск

1. Измените `VERSION`, например с `0.2.0` на `0.2.1`.
2. Добавьте в начало `CHANGELOG.md` раздел `## [0.2.1] - YYYY-MM-DD`
   с непустым описанием изменений. Пока поддерживаются стабильные версии `X.Y.Z`.
3. Отправьте изменения в `main`.

Workflow проверит метаданные релиза и тесты скрипта публикации, соберёт Qt 6 и console worker на Ubuntu 24.04, выполнит QtTest,
запустит QML с реальной генерацией и проверит окно в обеих схемах оформления. Только после успеха всех
проверок отдельное задание создаст тег `vX.Y.Z` на проверенном коммите и релиз.

Вложения релиза:

- `Obsidian-Extended-X.Y.Z-qt6-ubuntu-24.04-x86_64.tar.gz` — GUI, ресурсы и `start.sh`;
- `Obsidian-Extended-X.Y.Z-source.tar.gz` — исходники соответствующего коммита;
- `SHA256SUMS` — контрольные суммы архивов.

Описание берётся из раздела текущей версии в `CHANGELOG.md`. Сначала создаётся
черновик, затем загружаются вложения; публикация происходит после успешной
загрузки. При ошибке загрузки черновик остаётся неопубликованным.

## Повторный запуск и выпуск через тег

Коммиты с прежним `VERSION` проходят проверки, но не заменяют уже опубликованный
релиз. Для исправления опубликованной версии увеличьте номер и добавьте запись
в CHANGELOG. Скрипт не перезаписывает опубликованные описания и вложения.

При временной ошибке повторите неуспешное задание через Actions → Re-run failed
jobs. Черновик для того же коммита будет дополнен и опубликован. Конфликтующий
тег другого коммита не перемещается автоматически.

Можно отправить тег `vX.Y.Z` вручную: его номер обязан совпадать с `VERSION` в
помеченном коммите. Он также запускает полный цикл проверок. Запуск через
workflow_dispatch выполняет проверки без публикации.

Pull request не публикует релизы. Ошибки прав Actions или запрет создания тегов
нужно устранять в настройках репозитория; workflow не ослабляет эти ограничения.
