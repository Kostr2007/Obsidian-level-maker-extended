# Аудит проекта и переход к Studio

Дата: 2026-11-05. Базовая версия: 0.3.1 (`771f44c`). Результат: 0.4.0.

## Область проверки

Проверены сборка и упаковка, Qt frontend целиком, контракт экспорта настроек,
каталог параметров Lua, хранение конфигураций, запуск/отмена worker, чтение WAD,
точки входа построения уровней и автоматическая публикация. Это архитектурный
и интерфейсный аудит с исполняемыми проверками. Он не означает построчный
аудит всех prefab-файлов, сторонних библиотек или всех комбинаций игровых портов.

Инвентаризация через реальный `--export-ui`: 59 модулей, 474 параметра во всех
модулях. В исходном контексте экспорта Doom 2 / ZDoom доступны 29 модулей и
286 параметров. Числа зависят от игры, порта и дополнений. Отдельная Qt-проверка
использует стандартный для приложения Doom 2 / Boom и переход на Vanilla.

## Как устроен проект

| Часть | Файлы | Ответственность |
| --- | --- | --- |
| Сборка | CMakeLists.txt, source_files/qt_frontend/CMakeLists.txt | Qt приложение + отдельный console worker; исторический FLTK — явная опция |
| Определения | modules/, games/, ports/, engines/ | Параметры, defaults, зависимости и поддерживаемые возможности |
| Схема | scripts/qt_schema.lua, scripts/obsidian.lua | Экспорт protocol 1 из действующих Lua-определений |
| Frontend | source_files/qt_frontend/ | Компоновка, ввод, инспектор, автосохранение, процессы, WAD |
| Планирование | scripts/level.lua | Размеры, темы, последовательность генерации |
| Геометрия | scripts/area.lua, grower.lua, room.lua, connect.lua | Комнаты, связи, переходы и построение геометрии |
| Маршрут | scripts/quest.lua | Цели, ключи, зоны, посещения и возвраты |
| Бой и ресурсы | scripts/monster.lua, fight.lua, item.lua | Состав противников, моделирование боя, размещение предметов |
| Публикация | scripts/dev/, .github/workflows/material-you.yml | Сборка в пути с пробелами/скобками, проверки, архивы и версия релиза |

`Level_build_it` последовательно вызывает Area_create_rooms, Quest_make_quests,
Room_build_all, Monster_make_battles и Item_add_pickups. Studio управляет
входными параметрами этой цепочки. Изменение дизайна не требует переписывать её.

## Найденные проблемы и решения

| Наблюдение в 0.3.1 | Решение Studio |
| --- | --- |
| «Мир / Бой и предметы / Модули» отражают расположение старого интерфейса | Шесть категорий по задачам пользователя; отдельная классификация параметров смешанных модулей |
| Поиск ограничен текущей группой и оставляет все опции найденного модуля | Поиск по всем категориям; только совпавшие параметры, включая расширенные |
| Длинные англоязычные tooltips скрыты в отдельном диалоге | Постоянный инспектор, русские краткие пояснения и исходная справка |
| Крупные скругления и Material-оформление мешают плотной рабочей форме | Fusion, прямоугольные поля, радиус 4–6 px, нейтральный фон, один акцент |
| Первое открытие показывает много специальных опций | Основные настройки по умолчанию, переключатель и счётчик скрытых расширенных |
| Сложно понять разницу между steepness и room_heights | Раздельные пояснения и схемы перепадов высоты и высоты потолка |
| Новые сторонние модули нельзя заранее перечислить | Категория «Дополнения» и исходные названия/справка без потери значения |
| Узкий экран не вмещает три колонки | Инспектор открывается по «?» / Ctrl+I; seed и генерация остаются в нижней панели |

## Категории и точность данных

Каталог `studio-catalog.json` содержит явную классификацию 59 известных модулей.
Часть параметров misc, prefab_control и debugger перенесена в соответствующие
смысловые категории по ID. Например, освещение относится к оформлению, а не
к геометрии. Значения и порядок выбора вариантов остаются из Lua.

У каждого доступного неслужебного параметра одна категория. Заголовки `header_*`
не являются параметрами ввода и не дублируются как элементы управления.
Тест открывает настоящий Main.qml, собирает все категории и сравнивает их
объединение с полной схемой движка, проверяя также отсутствие дубликатов.
Отключённые модули сохраняют свои поля и пояснения; для изменения значения
пользователь включает модуль. Доступность по игре/порту определяет Lua.

Сортировка не меняет CONFIG.txt: общие параметры и секции модулей сохраняют
прежние ID. Импорт сохраняет неизвестные поля, как до Studio.

## Иллюстрации и пояснения

39 параметров получили русские краткие пояснения. Для 24 параметров используются
20 видов схем: размер уровня/комнаты, противники, сила состава и разнообразие,
ловушки, оружие, лечение, боеприпасы, предметы, секреты, открытые области,
пещеры, жидкости, коридоры, телепорты, перепады, потолки, освещение и линейность.
Одна схема может объяснять несколько параметров количества.

Схемы схематичны и показывают направление влияния. Они не обещают точное число
комнат, монстров или предметов. Значение float_size не подписано «число комнат»;
float_mons — множитель насыщенности; float_strength меняет состав противников,
а не здоровье каждого. Подписи для room_heights учитывают настоящие правила
Short/Tall из modules/misc.lua. Оригинальные longtip доступны в инспекторе.

Для остальных параметров показаны исходная справка, текущее и стандартное
значения. Для неизвестных дополнений не придумываются схемы и объяснения.

## Сохранившиеся ограничения

- Недетерминизм полной конфигурации в старом движке: см. ENGINE_NOTES.md.
- WAD preview проверяет структуру данных и рисует первую карту, но не доказывает
  доступность выхода, достаточность ресурсов или проходимость без прыжка.
- Справочник не является полным переводом всех 474 параметров и вариантов выбора.
- Для PK3/других форматов используется папка результата, не ложный WAD preview.
- Native Wayland, Windows/macOS и конкретные экранные дикторы требуют отдельных проверок.
- Масштабный перебор seed, баланс и детерминизм остаются в GENERATION_ROADMAP.md.

## Как проверить

```sh
./scripts/dev/build-linux.sh
QT_QUICK_BACKEND=software ctest --test-dir build/qt --output-on-failure --no-tests=error -R '^qt-core$'
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software ./obsidian --smoke-output "$PWD/build/qt-smoke"
python3 scripts/dev/check-qt.py
./scripts/dev/package-linux.sh
```

QtTest: классификация, неизвестный addon, поиск, смена порта, CONFIG round-trip,
валидация значений, binary/UDMF, настоящая генерация, переданный seed и отмена.
Xvfb: обе темы, F2, созданный WAD, поиск, 1050×760 / 1050×600,
окна Ctrl+I и Ctrl+G, чистый выход и отсутствие ошибок QML.
